# اختبارات الباك اند (محلي — بدون إنترنت)

هاد المجلد فيه محاكي صغير لواجهات Apps Script (`gas-mock.js`) وسيناريوهات تشغيل كاملة
على `Code.gs` (`run-tests.js`). الغرض منه إنك تتأكد إن منطق القراءة/الكتابة/الحفظ شغال
صحيح قبل النشر للشيت الحقيقي — وكمان يقيس عدد عمليات الشيت لكل سيناريو حتى تشوف أثر
أي تحسين أداء فوراً.

## التشغيل

```bash
# من مجلد tests
node run-tests.js ../Code.gs          # يفحص النسخة الحالية
node run-tests.js ../Code.gs --assert # نفس الفحص + يفشل (exit 1) لو في فحص راسب
```

- الشيتات كلها بالذاكرة — ما في اتصال بقوقل ولا تعديل على أي بيانات حقيقية.
- كل فحص "عمليات الشيت" هو عدّاد لعدد نداءات القراءة/الكتابة (getValues/setValues/appendRow/deleteRow...)
  وهاد مقياس كويس لمقارنة نسختين من الكود، مو رقم زمني مطلق.

## السيناريوهات المغطاة

- إعداد الشيت + تسجيل دخول (رقم سري واحد) + إنشاء جلسة.
- حفظ تقرير الاستلام (أول مرة + إعادة حفظ) وعدم تكرار الصفوف.
- حفظ تقرير المتبقي فوق نفس صف اليوم (ما بيمسح قيم الاستلام).
- طلبية الغد (استبدال كامل عند إعادة الحفظ) + الهدر + جرد العصيرات + استيراد مبيعات.
- `getDashboard` المجمّع (صلاحيات مالك/مدير) + `getFlaggedItems`.
- كاش القراءة (قراءة متكررة = صفر عمليات) وإبطاله عند الكتابة.
- الأمان: `clearAllEntriesData` بدون جلسة لازم ينرفض.
- الحذف المجمّع بصفوف متباعدة (صحة منطق دمج المجاميع المتتالية).
